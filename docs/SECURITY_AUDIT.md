## 1. Security Architecture & Threat Model

| Security Dimension | Implementation Standard | Defense Validation |
| :--- | :--- | :--- |
| **Authentication** | Stateless JWT (HS256) with role-based claims | Rejects forged tokens with 401/403 |
| **Machine-to-Machine** | `x-api-key` header with constant-time equality check | Protects edge sensor telemetry and drone pipelines |
| **API Rate Limiting** | Sliding-window in-memory token bucket | Protects CCTV inference endpoints against denial-of-service |
| **Evidence Sealing** | SHA-256 cryptographic digests on all evidence assets | Tamper-detection rejects modified or truncated files |
| **Default-Deny Policy** | Express router wildcard gating | All unauthenticated endpoints automatically blocked |
| **SQL Injection Defense** | Node.js SQLite parameterized statements | PRAGMA foreign keys & WAL journal mode enabled |

## 2. Chain of Custody & Statutory Non-Repudiation
Every forensic dossier generated by the system contains:
1. Unique cryptographic manifest identifier (`MANIFEST-<timestamp>-<hash>`).
2. Exact microsecond-stamped capture timestamp.
3. Operating commander identity and badge credential.
4. SHA-256 hash of original raw JPEG / MP4 bytes.
5. Digital signature stamp ensuring tamper-evident court admissibility.
